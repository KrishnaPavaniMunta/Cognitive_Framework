What Is Catastrophic Forgetting?

When a neural network is fine-tuned on new data, gradient updates that improve performance on new classes can overwrite the weight patterns responsible for old classes. The network "forgets" what it previously learned.

🔴 Classes at Risk

Old hospital-specific classes that received no new training images in V3 — e.g. surgical_light, nasal_cannula, glove, test_tube, infusion_pump, etc.

🟢 Classes Reinforced

The 3 overlapping Roboflow classes got extra images:
door (96), wheelchair (94), fire_extinguisher (100)

Mechanism: How It Happens Epoch by Epoch

Epoch 1 — Head Adapts to New Classes
The Detect head is re-initialized for 109 classes (was 106). Loss on new classes is very high → large gradients → head weights shift aggressively toward the 3 new classes.
Epochs 2–10 — Old Classes Under-represented
Each epoch, ~81% of batches have no old-hospital-class annotations. The backbone and neck features drift to optimise for the dominant Roboflow classes. Old-class activations weaken.
Phase 2 — Neck Unfrozen (freeze=15)
Layers 15–22 (deeper neck) are now trainable. These features are shared across all classes. With 4× more new-class images, gradient flow further biases them toward new classes.
Result — Rare Old Classes Forgotten
Classes with few training examples and no Roboflow reinforcement (e.g. surgical_scissor, hair_net, test_tube) see their recall drop significantly.

What the Freeze Strategy Did (and Didn't) Do

Freezing protects the backbone from gradient updates, preserving low-level features. But the unfrozen head and neck layers are still vulnerable to forgetting from imbalanced data.

Layers Phase 1 (freeze=22) Phase 2 (freeze=15) Effect on Forgetting
Backbone (0–9) Frozen ✔ Frozen ✔ Low-level features preserved
C2PSA / SPPF (10) Frozen ✔ Frozen ✔ Attention features preserved
Early neck (11–14) Frozen ✔ Frozen ✔ Upper-level features preserved
Deeper neck (15–22) Frozen ✔ Trainable ✗ ⚠ Drifts toward new classes
Detect head (23) Trainable ✗ Trainable ✗ Main source of forgetting

How to Prevent / Fix Forgetting

⚖️
1. Balanced Sampling (Most Impactful)
Cap per-class contribution so new datasets can't dominate. Upsample old hospital images to match the new dataset ratio — target ~50/50 split by image count. Add hospital_merged oversampling 4–5× in the merged dataset.
🔁
2. Experience Replay
Explicitly oversample all old hospital classes in the merged dataset, not just the new rare ones. For every new image seen, ensure at least one old-hospital image is seen in the same epoch.
🧊
3. Stricter Freeze for Phase 2
Keep freeze=22 in Phase 2 as well (head-only), or use a per-parameter learning rate that applies an even lower lr (1e-6) to the neck layers that serve old classes.
📊
4. Per-class mAP Monitoring
Run yolo val with the hospital_merged validation set only. If per-class AP for old classes drops >5% vs the pre-V3 model, trigger early stop and roll back.

Summary

  • Hospital V3 extended a 106-class model to 109 classes by merging 20,023 Roboflow images with 4,604 existing hospital images — a 4.3× imbalance.
  • The 2-phase freeze strategy protected backbone features but the Detect head and (in Phase 2) deeper neck layers were exposed to imbalanced gradient updates.
  • The 3 overlapping classes (door, wheelchair, fire_extinguisher) were reinforced by new data. The other 23 hospital-specific classes received no new images and are at risk.
  • Oversampling was applied only to new rare classes (spillage 3×, exit_sign 2×) — old classes were not oversampled.
  • Overall mAP50 reached 0.944 after 100 epochs — but this masks per-class forgetting of rare old classes.
  • The fix: balance the dataset (upsample hospital_merged 4–5×) before training V4, and run a per-class val on old classes after each training run.
